# AI Guardian API Documentation

## Overview

The AI Guardian API provides real-time risk assessment for routes. It evaluates various factors such as crime data, lighting conditions, time of day, weather, and traffic density to calculate a risk score for a given route.

## Base URL

```
http://localhost:5000
```

## Endpoints

### Risk Prediction

**Endpoint:** `POST /api/risk/route`

**Description:** Calculates a risk score for a route between two points and provides safer alternatives if available.

### User Feedback

**Endpoint:** `POST /api/risk/feedback`

**Description:** Allows users to submit feedback about route safety to improve the risk assessment model.

### Model Status

**Endpoint:** `GET /api/risk/model-status`

**Description:** Provides information about the current state of the risk prediction model, including training data count and model accuracy.

**Request Body:**

```json
{
  "start": "37.7749,-122.4194", // Start coordinates (latitude,longitude)
  "end": "37.7849,-122.4094",   // End coordinates (latitude,longitude)
  "mode": "walking"            // Travel mode (walking, driving, cycling, etc.)
}
```

**Response:**

```json
{
  "riskScore": 7.2,             // Risk score from 0 (safest) to 10 (most dangerous)
  "saferAlternatives": [       // Array of safer alternative routes
    {
      "riskScore": 4.8,         // Risk score of this alternative
      "distanceIncrease": "+15%", // How much longer this route is
      "timeIncrease": "+10%",    // How much more time this route takes
      "description": "This route avoids 2 high-crime areas" // Description of benefits
    }
  ],
  "explanation": "Route passes through 2 high-crime areas with poor lighting." // Human-readable explanation
}
```

**Error Responses:**

- **400 Bad Request:** When the request is invalid (missing or invalid parameters)
  ```json
  {
    "success": false,
    "error": "Please provide start, end coordinates and travel mode"
  }
  ```

- **500 Internal Server Error:** When there's a server-side error
  ```json
  {
    "success": false,
    "error": "Server error while predicting route risk"
  }
  ```

## Risk Score Interpretation

- **0-3:** Low risk - Generally safe route
- **3-5:** Moderate risk - Some minor risk factors present
- **5-7:** Medium risk - Several risk factors present
- **7-10:** High risk - Multiple significant risk factors present

## Example Usage

```javascript
const axios = require('axios');

async function checkRouteRisk() {
  try {
    const response = await axios.post('http://localhost:5000/api/risk/route', {
      start: '37.7749,-122.4194',
      end: '37.7849,-122.4094',
      mode: 'walking'
    });
    
    console.log('Risk Score:', response.data.riskScore);
    console.log('Explanation:', response.data.explanation);
    
    if (response.data.saferAlternatives.length > 0) {
      console.log('Safer Alternative Available!');
      console.log(response.data.saferAlternatives[0]);
    }
  } catch (error) {
    console.error('Error checking route risk:', error.response?.data || error.message);
  }
}

checkRouteRisk();
```

## Risk Calculation Logic

The risk score is calculated based on multiple factors, each contributing to the overall risk assessment:

### Factors and Weights

1. **Crime Hotspots (0-4 points)**
   - Each crime hotspot along the route adds 1.5 points to the risk score
   - Example: 2 crime hotspots = 3 points

2. **Poor Lighting Areas (0-3 points)**
   - Each area with poor lighting adds 0.75 points to the risk score
   - Example: 3 poorly lit areas = 2.25 points

3. **Time of Day (0-2 points)**
   - Night time (10pm - 6am): 2 points
   - Dawn/dusk (6am-8am, 7pm-10pm): 1 point
   - Daytime (8am-7pm): 0 points

4. **Weather Conditions (0-1 points)**
   - Fog: 1 point
   - Rain: 0.5 points
   - Clear: 0 points

5. **Traffic Density (0-1 points)**
   - Very low traffic (< 3): 1 point
   - Moderate traffic (3-5): 0.5 points
   - High traffic (> 5): 0 points

The final risk score is the sum of all these factors, capped between 0 and 10.

### Safer Alternatives Generation

Safer alternative routes are generated by:

1. Reducing the number of crime hotspots and poorly lit areas
2. Slightly increasing distance and duration (safer routes might be longer)
3. Calculating a new risk score based on these modified factors
4. Only including routes that have a lower risk score than the original

Each alternative includes:
- New risk score
- Percentage increase in distance and time
- Description of improvements (e.g., "avoids 2 high-crime areas")

### Risk Explanation

The API provides human-readable explanations based on the risk level:

- **Low risk (0-3)**: "This route is generally safe with minimal risk factors."
- **Moderate risk (3-5)**: Lists the minor risk factors present
- **Medium risk (5-7)**: Lists the moderate risk factors present
- **High risk (7-10)**: Lists all significant risk factors present

## Implementation Notes

In the current implementation, the risk assessment is simulated with random data. In a production environment, this would be replaced with real data from various sources:

1. **Crime Data:** Historical crime statistics for areas along the route
2. **Lighting Information:** Street lighting coverage and quality
3. **Time of Day:** Current time to assess risk based on daylight/darkness
4. **Weather Conditions:** Current weather that might affect visibility or safety
5. **Traffic Density:** How busy the route is with other pedestrians/vehicles

## Advanced Risk Model

The API now uses an advanced risk model that incorporates machine learning to improve risk predictions. This model:

1. **Uses TensorFlow.js** for more sophisticated risk calculations
2. **Considers additional factors** beyond the basic ones:
   - Population density
   - Emergency response time
   - Historical incidents
   - Route complexity
3. **Learns from user feedback** to continuously improve predictions
4. **Falls back to weighted calculation** if the model is not yet trained

### User Feedback API

**Endpoint:** `POST /api/risk/feedback`

**Request Body:**

```json
{
  "routeId": "abc123",           // ID of the route (from previous risk prediction)
  "userRiskScore": 8.5,         // User's perceived risk score (0-10)
  "feedback": "Felt unsafe due to poor lighting and few people around" // Optional feedback text
}
```

**Response:**

```json
{
  "success": true,
  "message": "Feedback recorded successfully"
}
```

**Error Responses:**

- **400 Bad Request:** When the request is invalid
  ```json
  {
    "success": false,
    "error": "Please provide routeId and userRiskScore"
  }
  ```

- **500 Internal Server Error:** When there's a server-side error
  ```json
  {
    "success": false,
    "error": "Server error while recording feedback"
  }
  ```

### Model Status API

**Endpoint:** `GET /api/risk/model-status`

**Response:**

```json
{
  "isInitialized": true,         // Whether the model is initialized
  "trainingDataCount": 250,     // Number of training samples
  "userFeedbackCount": 75,      // Number of user feedback entries
  "modelAccuracy": 0.87         // Current model accuracy (0-1)
}
```

## Data Collection

The system collects the following real-world data for risk assessment:

1. **Crime Data:** Number of hotspots, recent incidents, crime types, and crime rate
2. **Lighting Data:** Poor lighting areas, streetlight density, and average lux
3. **Weather Data:** Current conditions, temperature, visibility, and wind speed
4. **Traffic Data:** Traffic density, pedestrian activity, and congestion level
5. **Emergency Response:** Response time, distance to nearest police station and hospital

This data is collected for multiple points along a route and aggregated to provide a comprehensive risk assessment.
